# TezParts Telegram Bot

Claude-агент в Telegram, работающий на сервере 24/7 — независимо от того,
включён ли компьютер.

Это не «чат с ИИ». Внутри крутится полноценный агент (Claude Agent SDK):
он читает и пишет файлы, выполняет команды, использует твои скилы и
MCP-серверы. То же, что сессия Claude Code, только вход — через Telegram.

## Архитектура

```
Telegram ──long polling──> aiogram ──> очередь на чат ──> Claude Agent SDK
                                            │                    │
                                         SQLite            /data/workspace
                                    (сессии, расходы)     (постоянные файлы)
```

Три решения, которые определяют поведение системы:

**Очередь на каждый чат.** Агентный запрос идёт от 30 секунд до нескольких
минут. Два параллельных запроса в одном чате подрались бы за одну сессию
Claude и за одни и те же файлы. Поэтому внутри чата — строго по одному,
разные чаты работают параллельно.

**Сессия живёт в Claude, не в базе.** В SQLite хранится только `chat_id →
session_id`. Историю диалога держит сам Agent SDK и подхватывает её через
`resume`. Дублировать её у себя — лишний код и рассинхрон.

**`permission_mode = bypassPermissions`.** Спрашивать разрешение не у кого:
на том конце Telegram, а не терминал. Значит, агент может выполнить на
сервере что угодно. Единственная защита — белый список `ALLOWED_USER_IDS`
и то, что всё крутится в контейнере. Не запускай это на сервере, где лежит
что-то ценное помимо самого бота.

## Установка

### 1. Подготовка

- Бот у [@BotFather](https://t.me/BotFather) → токен.
- Свой Telegram ID у [@userinfobot](https://t.me/userinfobot).
- Ключ API на [console.anthropic.com](https://console.anthropic.com), либо
  подписка Claude (см. ниже).

### 2. Разворачивание на VPS

```bash
git clone <репозиторий> tezparts-bot && cd tezparts-bot
cp .env.example .env
nano .env                       # токен, свой ID, ключ API

mkdir -p data/workspace claude-home
cp workspace-template/CLAUDE.md data/workspace/CLAUDE.md

docker compose up -d --build
docker compose logs -f
```

### 3. Если используешь подписку Claude вместо ключа API

Оставь `ANTHROPIC_API_KEY` пустым и залогинься один раз внутри контейнера:

```bash
docker compose run --rm bot claude setup-token
```

Токен ляжет в `./claude-home` и переживёт пересборку образа.

### 4. Скилы

Клади их в `./claude-home/skills/<имя-скила>/SKILL.md` — контейнер монтирует
эту папку как `~/.claude`, и агент подхватывает их автоматически
(`setting_sources=["user", "project"]`).

## Команды

| Команда | Что делает |
|---|---|
| `/new` | Сброс контекста, следующее сообщение начнёт новую сессию |
| `/stop` | Прервать текущую задачу и очистить очередь чата |
| `/status` | Занят ли агент, длина очереди, текущая сессия |
| `/cost` | Расходы за 30 дней и лимит на запрос |

Всё остальное — обычный текст, уходит агенту как задача.

## Настройки

Все в `.env`, см. `.env.example`. Главные:

- `MAX_BUDGET_USD` — потолок стоимости одного запроса. Агент паникует и
  сворачивается, дойдя до него. Защита от бесконечного цикла.
- `MAX_TURNS` — потолок шагов агента за запрос.
- `CLAUDE_EFFORT` — глубина рассуждений: `low`/`medium`/`high`/`xhigh`/`max`.
  Прямо влияет на цену и качество.

## Локальный запуск (для разработки)

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
npm install -g @anthropic-ai/claude-code    # SDK запускает CLI как подпроцесс
cp .env.example .env && nano .env
PYTHONPATH=. python -m bot.main
```

## Что здесь ещё не сделано

- Голосовые сообщения и картинки — только текст.
- Файлы из Telegram не принимаются и не отдаются.
- Нет вебхука — только long polling (для одного пользователя этого хватает
  и не требует домена с TLS).
- Нет общего дневного лимита расходов, только на запрос.
